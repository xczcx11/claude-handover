# 断点交接 · 设计文档

**日期**：2026-10-03
**状态**：设计已定稿（待使用者审阅）
**仓名**：`claude-handover`（可改）

---

## 0. 一句话

把「**尾灯**（每条回复末尾的上下文余量）+ **断点存档**（compact/clear 前把进度落成文件）」打成**一个 git 仓**，
让新机器 **clone 一次** → 用 skill 引导装好尾灯 → **重启一次** → 完工。

---

## 1. 名词（先定死，后面全靠它）

| 名词 | 指什么 | 在哪 |
|:--|:--|:--|
| **交接** | ★ **总名**。把下面两层当**一个**功能看时的叫法 | 概念 |
| **尾灯** | **感知层**。挂在每条助手回复末尾的一行上下文余量；到 85% 亮 ⚠ | `MessageDisplay` hook |
| **断点存档** | **执行层**。把「现在到哪 / 下一步 / 已作废」落成文件 | `project-checkpoint` skill |

```
        ┌── 感知层：尾灯 —— 85% 亮 ⚠
 交接 ──┤
        └── 执行层：断点存档 —— 落文件
                 ↓
              然后才 compact / clear（不丢东西）
```

★ **可当动词**：「跑一遍交接」。

---

## 2. 目标 / 非目标

### 目标
1. 新机器（**Windows + VSCode 扩展 + Claude Code**，与本机同构）上，`git clone` 本仓后，**由 skill 引导**装好尾灯。
2. **本机现有功能一模一样**（尾灯照常显示）。
3. 安装逻辑**可诊断、可替换**（每台机器环境略有不同）。
4. 装好并确认后，**安装件从本机移除**，日常调用不再有"检测"这一步。

### 非目标（明确不做）
- ❌ 不做 plugin / marketplace（理由见 §3）
- ❌ 不打包终端 `statusLine`（终端自带能力，非本方案必需）
- ❌ 不做**全自动**安装 —— 接受 `1 次 clone + 1 次重启` 的代价
- ❌ 不自带更新机制（autoUpdate）—— 更新 = `git pull` + 重跑 installer

---

## 3. 关键约束（★ 全部已查证，这是整个设计的**前提**）

| # | 事实 | 证据 | 对设计的影响 |
|:--:|:--|:--|:--|
| 1 | **skill 不能自带常驻 hook** | SKILL.md 的 `hooks` frontmatter 只在**skill 调用域内**生效 | ⇒ skill 只能当**安装器**，不能当**宿主** |
| 2 | **plugin 能带 `hooks.json`** | plugin 启用 = 自动注册 | 但见 #3 |
| 3 | ★ **`MessageDisplay` 从 plugin 加载在 Windows 不触发** | 官方 issue **#69380**（OPEN）；`Stop` 等其它事件正常 | ⇒ ★ **尾灯必须写进 `settings.json`，不能走 plugin** |
| 4 | **扩展不渲染 Stop hook 的 `systemMessage`** | 扩展目录搜 `systemMessage` = **0 命中**（从未实现） | ⇒ 旧的 Stop hook 在扩展里**从来没显示过** |
| 5 | **settings.json hook 热重载有缺陷** | issue **#57852**（原子保存使监听失效） | ⇒ 装完**大概率要重启** |
| 6 | **没有 install-time hook** | `Setup` 只在 `--init` / `--maintenance` 触发；`SessionStart` 每次会话都跑 | ⇒ 没有"装完自动跑一次"的钩子 |
| 7 | **Claude Code 自己的账本公式** | 二进制 `C15`：`input + cache_read + cache_creation` | ⇒ ★ 我们的取数**与核心同源**，可信 |
| 8 | **默认窗口常量 `aPq = 200000`** | 二进制 `var aPq=200000`；`HN(模型,…)` 对认不出的模型返回它 | ⇒ 中转端点下 UI 报 200k 是**错的** ⇒ 本方案用 `ctx_config.json` 覆盖 |

### 由 #1~#3 推出的结论

> **打包单位 = 一个 git 仓，其根目录【就是】skill 目录。**
> 尾灯由 **skill 引导写进 `settings.json`**（绕开 #3）。
> —— 这既满足了"自动配置"，又**不与已知 bug 正面冲突**。

## 4. 架构

### 4.1 目录结构

```
【git 仓】project-checkpoint/          ← 仓根目录【就是】skill 目录
├── SKILL.md                            ← ① 存档规程(泛化后) ② 安装/自检段(装好后自动剥除)
├── scripts/
│   ├── ctx_core.js                     ← 取数核心(单一权威)
│   ├── ctx_msgdisplay_hook.js          ← 尾灯
│   └── install.js                      ← check / apply / finalize 三档
├── optional/
│   └── ctx_stop_hook.js                ← ★ 可选件(默认不装，见 §7)
├── templates/
│   └── ctx_config.json                 ← 窗口配置模板
├── README.md                           ← 给人看:安装 + ★恢复命令
└── .gitignore                          ← 挡运行时产物(双保险)
```

```
【运行时·不在 git 里】~/.claude/handover/
├── ctx_core.js                         ← 从仓里拷来的
├── ctx_msgdisplay_hook.js
├── ctx_config.json                     ← 本机窗口值(如 1000000)
├── _handover_state.json                ← ★ 状态机 marker
└── _hook_trace_v1.log                  ← 痕迹日志(写这儿 ⇒ 不脏 git)
```

### 4.2 职责边界（本节最要紧的一条）

| | 谁 | 为什么不合并 |
|:--|:--|:--|
| **源** | git 仓 | 要干净、要能版本化、要能分发 |
| **运行时** | `~/.claude/handover/` | 日志和本机配置**天天在写**，放仓里会把 git 工作区弄脏 |

★ **运行时目录名从 `statusline/` 改为 `handover/`** —— 原名是当年为终端状态栏起的，现在尾灯也住在里面，名不副实；且与总名「交接」对齐。

## 5. 安装生命周期

### 5.1 状态机（marker：`~/.claude/handover/_handover_state.json`）

```
   (marker 不存在)         installed_unverified            verified
       未装         →    已装·待确认(等重启+使用者确认)  →   已确认(收尾完成)
         │                       │                              │
     触发安装             问"尾灯出来了吗?"               直接进存档规程
                                                                零检测
```

### 5.2 `install.js` 三档（每档都幂等）

| 档 | 干什么 | 写东西吗 |
|:--|:--|:--|
| `--check` | **只读**检测，吐**结构化报告** | ❌ 一个字节都不写 |
| `--apply` | 拷脚本 → 写配置 → 合并 `settings.json` → marker=`installed_unverified` | ✅ |
| `--finalize` | marker=`verified` → 删 `install.js` → 剥掉 SKILL.md 的安装段 | ✅ |

`--check` 报告必须覆盖：

```
node 在 PATH ？            ✓/✗
~/.claude/ 在 ？           ✓/✗
settings.json 在 ？        ✓/✗   ★ 不在 ⇒ 报告里点明"必须新建，否则会静默跳过"
MessageDisplay 已注册 ？    ✓/✗
运行时目录 ？              ✓/✗/陈旧
```

★ **"陈旧"怎么判定（不许含糊）**：每个脚本导出一个版本常量
（`ctx_core.js` → `VERSION = 'v5'`，尾灯同理）；
`--check` 同时 `require()` **仓里的**和**运行时的**两份，比对 `VERSION`。
不等 ⇒ 报"陈旧"，`--apply` 时覆盖拷贝。**不靠文件时间戳、不靠字符串猜测。**

### 5.3 完整流程

**① 第一次调用 `project-checkpoint`（本机未装）**

```
读 marker → 无
  ↓
scripts/install.js --check        ⇒ 摊报告
  ↓
问使用者"要装吗？"
  ↓ 同意
scripts/install.js --apply
  ↓
"装好了 —— ★ 请重启 Claude（settings.json 的 hook 要重启才武装）。重启后回来说一声。"
```

**② 重启后，第二次调用**

```
marker = installed_unverified
  ↓
问"尾灯出来了吗？"（消息末尾那行 [ctx]）
  ↓ 答"出来了"
scripts/install.js --finalize
  ↓
"收尾完成，以后调用不再检测。"
```

**③ 以后每次调用**

```
marker = verified ⇒ 读一个小 JSON，直接进存档规程
```

### 5.4 失败路径（使用者新增点 1）

```
--check 报 FAIL / --apply 报错
  ↓
报告必须带齐四样：哪一步 · 原始错误 · 本机实测值 · 建议怎么改
  ↓
SKILL.md 指示本机 Claude 按报告适配，三条路：
  ① 改环境      例：没 node ⇒ 让使用者装，或改指其它解释器
  ② 就地改脚本  例：家目录/路径分隔符解析不对 ⇒ 改 install.js
  ③ 手工补      把该写的 JSON 片段给使用者，或 Claude 自己 Edit settings.json
  ↓
改完重跑 --check，直到全绿
```

★ **设计原则**：不把 `install.js` 做聪明，把它做成**可诊断、可替换** ——
因为"每台机器略有不同"枚举不完，**能枚举的只有"失败长什么样"**。

★ 就地打的补丁**不会自动回流上游**；要不要提回 git 仓是使用者的选择。

### 5.5 ⚠️ 后遗症（已与使用者确认）

`--finalize` 删掉 `install.js` 后，**本机没有修复入口**。恢复动作（★ 必须写进 README）：

```bash
git -C ~/.claude/skills/project-checkpoint checkout .   # 把 install.js / SKILL.md 拿回来
node ~/.claude/skills/project-checkpoint/scripts/install.js --check
```

实在不行：删掉整个目录重新 clone。
**"平时清爽"就是拿"出事了要动 git"换来的** —— 使用者已确认接受。

★ **另一个必须交代的副作用**：`--finalize` 删 `install.js`、剥 `SKILL.md`，
这两个动作会让 **git 工作区变脏**（`git status` 显示 deleted / modified）。
**这是预期的，不是错误** —— 仓里的原件没动，只是本机这份被"消费"掉了。
⇒ 后果：以后在这个目录里 `git pull` 可能因本地改动而冲突。
⇒ 处理：`git checkout .` 再 pull（这也正好是 §5.5 的恢复命令）。
★ 这一条**写进 README**。

## 7. 本机迁移（一次性）

| # | 动作 |
|:--:|:--|
| 1 | 新建 `~/.claude/handover/`，把 `ctx_core.js` / `ctx_msgdisplay_hook.js` / `ctx_config.json` 挪进去 |
| 2 | `settings.json` 里 **MessageDisplay hook 的命令路径**改指 `handover/` |
| 3 | `statusline.js` 里 `require('./ctx_core')` → `require('../handover/ctx_core')`（★ 一行，别弄坏终端状态栏） |
| 4 | ★ **摘掉 `settings.json` 里的 `hooks.Stop`** |
| 5 | 建 `$REPO\`，放 SKILL.md（泛化后）+ scripts/ + templates/ + README.md |

### 为什么摘 Stop hook（★ 使用者已确认）

- 它输出 `{"systemMessage": …}`，而**扩展目录 `systemMessage` = 0 命中** ⇒ **本机从来没显示过**（痕迹日志里响了 20+ 次，使用者一次没看见）
- 使用者看到的 `[ctx]` 行 **100% 来自尾灯**
- ⇒ **对使用者看得见的东西零影响**；终端下反而少一行重复
- 脚本留仓里当**可选件**（`optional/ctx_stop_hook.js`），要加回去一条 `settings.json` 即可

## 8. 验收标准（六条，少一条不算完）

| # | 验什么 | 怎么验 |
|:--:|:--|:--|
| 1 | ★ 本机尾灯**没被迁移弄坏** | 发一条消息，末尾仍有 `[ctx] NN% 已用 · 剩 NNNk / 1M` |
| 2 | 日志落到新位置 | `~/.claude/handover/_hook_trace_v1.log` 有新增行且带 `cwd=` |
| 3 | ★ **另一个项目**也正常 | 在 `<项目A的CC目录名>` 发一条，尾灯照常（回归） |
| 4 | `--check` 本机全绿 | `node scripts/install.js --check` |
| 5 | ★★ **模拟新机器** | clone 到临时目录跑 `--check` ⇒ 报告应说"**未装**"，且**一个字节都没写** |
| 6 | 幂等 | `--apply` 连跑两次，`settings.json` 里**只有一条** MessageDisplay |

★ 第 5 条是**整套设计里最值钱的验收**：用"克隆到别处"模拟新机器，**不碰真环境**就能证明"新机器上的第一次检测"是对的。

## 9. 未决 / 风险（★ 不藏着）

| # | 事项 | 现状 |
|:--:|:--|:--|
| 1 | ★ **窗口值 `1000000`** | 由压缩点反推（实测会话撑到 **1,009,621** 才压缩），**非官方规格**；若某天压缩点明显不在 ~1M，改 `templates/ctx_config.json` |
| 2 | **clone 后 skill 是否需重启才被识别** | **未实测**。README 里写"没出现就重启一次"兜底 |
| 3 | **#69380 若被修复** | 届时可考虑改走 plugin（更自动）；**当前不可以** |
| 4 | **终端下是否真出两行** | 未实测（不影响本机，本机是扩展） |
| 5 | **SKILL.md 泛化的具体措辞** | 本文件只给了对照表，逐句改写留到实现阶段 |
| 6 | **install.js 的 PowerShell 兼容** | ★ 本机是 Git Bash + `node`；若新机器无 bash，需确认 hook 命令的 shell（已知：Windows 上无 Git Bash 时默认用 PowerShell） |
